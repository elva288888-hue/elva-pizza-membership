## 当前支付状态

`cloudbase-config.js` 中当前配置为：

```js
payments: {
  mode: "mock"
}
```

这表示：

- 微信支付：内测模拟确认，不会真实扣款。
- 支付宝：打开本地模拟支付页，不会真实扣款。
- 会员余额支付：会真实扣减系统里的会员余额，并写入订单和流水。
- 消费者端充值：内测模拟确认后才增加会员余额，并写入后台流水。

正式收款前，不要把内测模拟支付当作真实支付凭证。

## H5 真实支付可选路线

### 路线 A：微信内 H5 / JSAPI 网页支付

适合顾客在微信里扫码打开 H5 页面。

需要准备：

- 已认证服务号或可承载网页授权的微信主体
- 微信支付商户号
- 公众号 AppID 与商户号完成绑定
- API v3 密钥
- 商户 API 证书序列号
- 商户 API 私钥
- 支付回调 HTTPS 域名

系统改造：

- 增加后端 `createWechatJsapiPayment` 接口
- 前端提交订单草稿后调用支付接口
- 微信支付成功异步回调后，后端再创建已支付订单、充值流水或扣款流水
- 前端只负责展示支付状态，不直接相信用户端成功回调

### 路线 B：微信 H5 支付

适合顾客从 Safari、短信、浏览器或非微信 App 打开 H5。

需要准备：

- 微信支付商户号
- 开通 H5 支付产品权限
- 已备案支付域名
- API v3 密钥、证书序列号、商户私钥
- 支付回调 HTTPS 域名

注意：如果大多数顾客是微信扫码进店点餐，路线 A 通常比路线 B 更贴近实际使用。

### 路线 C：支付宝网页支付

适合补充支付宝付款。

需要准备：

- 支付宝开放平台应用
- 支付宝商户能力
- 应用 AppID
- 应用私钥和支付宝公钥
- 支付回调 HTTPS 域名

系统改造：

- 增加后端 `createAlipayPayment` 接口
- 前端跳转支付宝支付页
- 支付宝异步通知验签成功后，后端再入账

## 推荐执行顺序

1. 继续用 H5 内测：验证菜单、下单、后台接单、会员余额、充值规则、地址保存和退款。
2. 内测期间在线支付先保持 `mock`，店家可以线下确认付款。
3. 如果要 H5 真支付，优先接微信内 JSAPI 网页支付，再接支付宝。
4. 等业务流程稳定，再决定是否注册小程序并迁移消费者端。

## 上线前必须补齐

- 配置真实店长手机号和腾讯云短信验证码。
- 准备正式 CloudBase 生产环境，避免测试数据污染正式数据。
- 确定真实支付路线并完成商户资料、证书和回调配置。
- 支付成功必须以后端回调为准，不能以前端弹窗确认或跳转成功为准。
- 开启数据库备份和导出流程。
